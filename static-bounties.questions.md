# Static bounty boards, assumptions

- DE lists four boards with zero jobs: Zariman (The Holdfasts), Entrati Lab (Cavia), Vox Solaris and Höllvania (The Hex). Both feeds agree, both fixtures show it. Those four are filled from the drop tables, nothing else is.
- The drop tables publish rotation C only for all four boards today, one final stage pool per level band. The reader keeps whatever rotations the file has, so A and B appear on their own if DE ever publishes them.
- The scrape repeats an item once per stage it can drop from. Where that happens the highest chance is kept, so a job lists each item once.
- A filled board takes the expiry DE prints for that syndicate mission, the rotation still cycles. Vox Solaris carries the daily expiry rather than the 2.5 hour one, DE prints no other clock for it and Profit Taker does not rotate anyway.
- If a feed sends no expiry for the board at all, the fallback is the next 2.5 hour boundary aligned to the epoch. The wiki gives 2.5 hours for the Zariman and Cavia rotations, matching the Holdfasts cycle already in `de.ts`, but the true boundary rides the Cetus clock, not the epoch. Only a feed missing the board entirely lands here.
- Standing on a filled job is 0. Neither feed nor drop table says what a fixed board pays per stage, and the panel leaves the number out rather than printing a zero.
- `BountyJob.title` is new and optional. Profit Taker runs three phases at level 40 to 60, so the level alone cannot tell those jobs apart. It is set only when a board repeats a level band.
- `Bounty.static` and `BountyJob.rewardTable` are optional, so rows written before this slice still validate.
- The reward names come from the drop tables, so a filled board's `rewards` read like "15,000 Credits" and "5X Gyromag Systems" rather than the plain item names the live boards use. Rules match on those strings.
- `convex/ingest/static-bounties.json` is regenerated by `node scripts/build-static-bounties.mjs`, it is not fetched at runtime. Rerun it after a game update.
